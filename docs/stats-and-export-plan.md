# TapMoney：统计榜单与本地导出方案

2026-10-14。已上线：三种本地导出、CSV、收益增长和名次变化。当前收益表格同时显示昨日、本月、累计三列及可计算的增长率，点击列头排序；手机端在表格内横向滚动。下文保留最初方案；日活 / 曝光榜、作者汇总等后续阶段尚未上线。

## 已核实的事实

使用本机现有 TapTap 登录、当前查询工作室和游戏 `959305` 做了只读请求：

| 数据 | TapSulor 使用的接口 | 字段 / 参数 | 本次结果 |
| --- | --- | --- | --- |
| 广告收益 | `/api/mini-app/v1/ad/payout-report-data` | `revenue`；`start_time` / `end_time` | 成功；2026-10-13 为 ¥396.05 |
| 日活、新增 | `/api/mini-app/v1/stats-by-day/device` | `active_device_num`、`new_active_device_num`；`start_date` / `end_date` | HTTP 403，`forbidden`，禁止访问 |
| 曝光、点击、转化 | `/api/dashboard/v2/stats-by-day/position/cn` | `impression_cnt`、`click_cnt` 等；`platform=android` | HTTP 403，`forbidden`，禁止访问 |

`/api/user/v1/me` 同时返回成功，因此不能把这两个 403 当成登录失效。当前证据仅说明这套登录与查询参数不能取得该游戏的这两类数据，不能据此断言所有其他游戏都无法取得，也不能承诺能查询所有人的日活、曝光。

## 榜单与页面

建议把标题变成一个小型选择器：`收益榜 ▾`，菜单为收益榜、日活榜、曝光榜。沿用一张表，搜索、刷新、下载图标仍放在标题同一行。

| 榜单 | 第一版时间切换 | 主数值 | 后续可增加 |
| --- | --- | --- | --- |
| 收益榜 | 昨日 / 本月 / 累计 | 小游戏广告收益 | 较前日、上月同期、名次变化 |
| 日活榜 | 昨日 | 活跃设备数 | 7 日均值、本月日均、新增榜 |
| 曝光榜 | 昨日 / 本月 | Android 商店曝光次数，最终名称待口径核对 | 较前日、点击及转化详情 |

日活不能把每日设备数相加后叫“本月活跃用户”或 MAU：同一设备会跨日重复。后续月度展示应叫“本月日均活跃”，有缺日时需显示数据覆盖情况。

表格保持排名、游戏、主数值三个主要列；增长幅度可作为数值下的小字。点游戏打开现有详情，曲线指标用选择器切换，避免叠加多条单位不同的曲线。

榜单只覆盖管理员添加的游戏，不能包装为全 TapTap 总榜。无权限、未采集、失败不填 0，不进入有效排名；真实 0 正常参与排序。每个指标独立保存状态和统计日期，一个接口失败不影响其他数据。旧数据标明旧日期，不能混入昨日榜比较。

目前该游戏的日活、曝光权限尚未通过验证，因此优先完成能使用真实收益的功能。日活、曝光数据入口可复用现有采集架构，但有成功数据后才对外开放相应榜单。

## 三类导出

| 导出 | 内容 | 入口 |
| --- | --- | --- |
| 游戏统计分享卡 | Logo、名称、作者、昨日 / 本月 / 总收益、当前选定曲线、统计日期 | 游戏详情的下载图标 |
| 榜单分享图 | 当前榜单、当前时间范围、游戏 Logo、名次、数值、统计日期 | 标题行的下载图标 |
| 游戏素材 | 公开 Logo、截图；有可靠来源时再增加宣传图 | 游戏详情内的素材入口 |

统计卡默认使用真实收益。日活、曝光获准后才加入可用指标。缺数据显示“—”，曲线在缺日处断开。曲线范围沿用详情中的 30 天、90 天、全部。

昨日榜单明确写“2026-10-13”；本月榜单写“2026-10-01 至 2026-10-13”，不只写相对日期。导图沿用当前搜索和排序；有筛选时注明筛选范围，避免把筛选结果误当完整榜单。默认前 20 名，一页 20 款，全部导出按页生成，避免手机超长 Canvas 失败。图中名次与网页一致。

分享图采用固定 1080 像素宽度、浅色背景、深色文字和单一曲线强调色。保留小型来源与日期，不加入网页操作按钮、管理入口或无关描述。导出不要求管理员登录。

素材支持单图下载和“全部素材 ZIP”。保留图片响应的实际格式和公开返回尺寸，不把压缩处理地址宣称为未压缩原图。某款游戏没有截图时只提供已取得的素材；某张下载失败不导致整个 ZIP 消失，应列出未成功项。

## 本地生成方式

由浏览器读取已有公开快照与图片，使用 Canvas 绘制统计卡 / 榜单，`toBlob()` 生成 PNG，Blob 下载链接保存文件；支持的手机可调用系统分享，不支持则下载或预览保存。无需图片生成 API，不上传用户选项或导出文件。

原始素材使用 `fetch → Blob → 下载 / 本地 ZIP`，无需重新绘制。ZIP 库仅在点击批量导出时加载，所有生成都在访客设备内进行。图片过多时分批处理、释放 Object URL。

优先采用专门的导出绘图模板，复用数值格式和曲线计算，保证桌面与手机输出一致，不依赖截取当前屏幕或截图库对 CSS 的支持。

图片采用两步策略：

1. TapTap 支持跨域的图片可直接读取。加载失败则统计卡用名称首字占位，榜单照常导出。
2. QQ 头像及需要稳定下载的素材，由现有本机每日采集脚本预先下载公开图片到站点静态目录，保存同源地址。访客从静态站点读取；无需运行时图片代理，也无需服务器生成图片。新增资源在下一次同步前使用占位，管理 UI 可保留原链接用于普通展示。

静态资源采集不携带开发者 Cookie；限制允许的图片域名、文件类型与体积，缓存并去重。只发布当前公开游戏与作者所需的资源。

## 实施顺序与额外建议

1. 先做游戏统计卡、昨日 / 本月收益榜导图，以及 Logo / 截图单图与 ZIP 导出。这些都有可验证的数据来源。
2. 增加增长与名次变化；本月与上月同期天数比较。前日为 0 时不显示无穷大百分比；历史不完整时不做推断。
3. 拿到日活、曝光的成功响应并核对口径后，加入独立采集状态、日报历史和对应榜单。
4. 后续做作者汇总榜与浏览器本地 CSV 导出。作者榜叫“关联游戏收益”，不能当作者个人实际所得；同一游戏绑定多人时可能在多个作者行重复出现，不能将作者行再次求和充当全站收益。

暂不优先加入留存榜、人均时长榜或收入预测：会扩大权限依赖和口径问题，也会增加页面复杂度。每活跃设备收益等衍生指标，须在收益与活跃范围、平台、日期一致后再考虑，不能称为官方转化率。

后续实现验收应覆盖：同快照排序与导出一致、日期正确、失败与真实 0 分开、图片跨域回退、长榜分页、ZIP 部分失败、中文字体就绪、手机保存以及导出文件不含 Token / Cookie。
